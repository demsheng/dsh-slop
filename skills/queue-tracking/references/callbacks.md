# Queue callbacks

Callbacks are optional. Submit an existing wrapper unchanged and track its job id with polling; do not replace the dispatcher, add wrappers, split submissions or move logs to accommodate monitoring. For a compatible Bash script already being created or edited, call `slop_queue_prepare` once per intended execution and insert or source the returned helper after the scheduler directives and before environment setup, without changing those directives, existing traps or exit status. Reuse that helper and bind its Queue id to the exact submitted job id or process handle with `slop_queue_track`. If integration would change the workflow, retain polling. Track a DPDispatcher controller without registering its children, and never discover or register child jobs automatically. Do not instrument running work. Callbacks report only startup, exit and optional named phases, and callback failure must not fail the workload.
